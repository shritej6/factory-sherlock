### API contract

The contract is the generated OpenAPI document. scripts/development/export_openapi.py imports the FastAPI application and writes `app.openapi()` to docs/api/openapi.json; the routes and Pydantic schemas are the source and the JSON is never edited by hand. The parts the frontend depends on:

- Error body. Every error response matches `ErrorResponse`: `error`, `message`, `details`, and a required `request_id`. frontend/src/services/http.ts turns any non-2xx response into an `ApiError` with status, error code, details, and request id; a non-JSON body falls back to a generic message and a failed fetch becomes a `NetworkError`.
- Pagination envelope. Six list endpoints (orders, batches, inspections, investigations, machine events, alerts) return `items`, `total`, `limit` (1 to 500, default 50) and `offset` (0 to 1,000,000). `Page<T>` and `PageParams` in frontend/src/types/api.ts mirror this and components/ui/Pagination.tsx reads `total`.
- Status filters. `GET /production-batches` and `GET /investigations` accept a repeatable `status` parameter typed as an array of the matching enum; `buildQuery` in http.ts sends an array as repeated keys. `GET /production-orders` takes a single `status`.
- Status counts. `GET /production-orders/status-counts` returns `OrderStatusCounts`, one integer per order status with every key present. `useOrderStatusCounts` in frontend/src/hooks/queries.ts feeds both the Overview tile and the Analytics chart.
- Batch rows carry `order_number`, so the batch table needs no second lookup of orders, and `GET /analytics/queries` marks each catalogue entry `runnable` and lists its `parameters`, so the SQL Explorer shows only the inputs a query binds.

## 3. Decisions, alternatives, assumptions, constraints, and rationale

| Decision | Alternative considered | Rationale |
|---|---|---|
| Status filters applied by the API (`status` on batches and investigations) | Request the 500-row lookup page and filter in the browser | The list cap is 500 rows, so a client filter would silently miss anything beyond the first page and the displayed total would be wrong. The server applies `WHERE status IN (...)` before pagination, so `total` reflects the filter and the Overview counts open cases from a one-row filtered page. |
| One `GET /production-orders/status-counts` request | Six single-row list requests, one per status, reading each envelope total | The earlier hook issued one request per order status to build one chart. One GROUP BY returns every count in one round trip with every key present, and the query key shares the `orders` root so any order mutation refreshes it. |
| Per-subgroup control limits drawn as stepped lines | One constant UCL and LCL computed from the average sample size | Query 10 returns `ucl` and `lcl` per row: grand mean plus or minus three pooled standard deviations over the square root of that subgroup's sample count. A small subgroup gets wider limits and is not flagged against limits meant for a larger one; `toControlChartSeries` judges each point against its own limits and ControlChart.tsx draws them with `type="stepAfter"` around a straight grand mean. |
| Shared ErrorNotice with the request id for every mutation | Keep InlineNotice with a formatted message string | Only ErrorState showed the request id, so a failed form action could not be matched to a server log line. Components now keep the raw error and hand it to ErrorNotice, which renders the same message and id as ErrorState; the CSV import test asserts the id is shown. |
| End-to-end sign-in through the API, with one form login under tracing off | Type the demo password into the login form in every spec | A Playwright trace records typed values and request bodies and is uploaded with the CI report, so `signIn` in e2e/support/auth.ts obtains a token with Node's `fetch` outside the browser and stores it under the app's `localStorage` key. login.spec.ts still types the password because the form itself is under test, and runs with `test.use({ trace: 'off' })`. |
| Pagination clamps back to the last page with rows | Show an empty page past the end, or jump to the first page | After a delete or a narrowed filter the offset can run past the total. Pagination.tsx shows `floor((total - 1) / limit) * limit` and requests it from an effect, so the user stays near where they were; screens also reset the offset when a filter changes. |
| Explicit focus management in the drawer and in Disclosure | Browser default, which drops focus to the document body when the focused element is removed | The mobile drawer precedes the Menu button in DOM order, so focus moves to its first link on open, Escape returns it to Menu, and the aside is `inert` while closed. Disclosure returns focus to its toggle when a form closes itself, and BatchActions moves focus into the reason field and back. Each behaviour has a test. |

Assumptions and constraints: the frontend speaks only to `/api/v1`, through the Vite proxy in development; the demo scenario is dated 2026-11-02, so default windows run 2026-11-01 to 2026-11-05; no screen creates products, machines, or material lots. The e2e suite writes one closed investigation and one quarantined lot per run, and `make reset-demo` restores the demo database.

## 5. Lessons learned at this milestone

- In development every browser reaches the API through the Vite proxy from 127.0.0.1, so a login throttle keyed on the client address locked every demo account after five wrong passwords from one person. The address bucket now applies only after a failed verification, and every self-started uvicorn passes `--no-proxy-headers` (commit 18a5903, SECURITY.md).
- Changing six list endpoints from a bare array to the `items, total, limit, offset` envelope broke eight API tests and the e2e helper written against the array shape on parallel branches (commits 7bca7ac and a95df14). A contract change needs a written note to every consumer being built at the same time.
- Two text colours passed a visual check and failed the WCAG 2.1 AA measurement: `ink-faint` on the canvas was 4.42:1 and the request id line on the error background was 3.95:1. Shifting the token from #697280 to #646d7b and moving the request id to `ink-muted` fixed both; the ratios were computed, not estimated.
- The fetch helper always puts a `body` key in the request init, undefined when there is none. The overdue check used to send `{}` to an endpoint that declares no body (commit 1140e0e), and the regression test asserts that `body` is undefined rather than absent.
