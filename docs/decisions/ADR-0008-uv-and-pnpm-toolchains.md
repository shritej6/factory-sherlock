# ADR-0008: uv for the Python backend and pnpm for the frontend

## Status

Accepted. Recorded 2026-11-03. `uv` is implemented in `backend/pyproject.toml` and `backend/uv.lock`; `pnpm` is implemented in `frontend/package.json` and `frontend/pnpm-lock.yaml`.

## Context

The repository contains two toolchains: a Python 3.12 backend (FastAPI, SQLAlchemy 2, Alembic, Pydantic v2) and a React + TypeScript frontend built with Vite, Tailwind, and Recharts. Several people and three AI coding assistants work on the codebase, so installs must be reproducible from lock files, fast to repeat, and expressible as one-line commands in the documentation.

## Decision

Backend:

- Use `uv` as the single tool for creating the virtual environment, resolving dependencies, locking (`uv.lock`), and running commands. `pyproject.toml` declares runtime dependencies and a `dev` dependency group (`pytest`, `pytest-cov`, `httpx`, `ruff`, `mypy`, `types-pymysql`) and a `docs` group (`playwright`, used by `make render-diagrams`); the build backend is `hatchling` with the `app` package.
- Every documented command is prefixed with `uv run` so it uses the project environment without activation: `uv sync`, `uv run alembic upgrade head`, `uv run python -m app.seed`, `uv run uvicorn app.main:app --reload`, `uv run pytest`, `uv run ruff check .`, `uv run mypy app`.
- `ruff` (line length 100, rule sets `E, F, I, B, UP, N, SIM, RUF`, `B008` ignored for FastAPI dependency defaults, `migrations/versions` excluded so autogenerated files keep Alembic's formatting, `E501` relaxed under `tests/`) and `mypy --strict` with the Pydantic plugin are the configured quality tools. `backend-ci.yml` runs `uv sync --locked --all-groups`, Ruff, mypy (a blocking step; `mypy --strict` reports no issues on 69 source files), migrations, and pytest with coverage against a MySQL 8.4 service container.
- Scripts under `scripts/development/` that need the application (`reset_database.py`, `export_openapi.py`) are run with `uv run` from the `backend/` directory so they can import `app`.

Frontend:

- Use `pnpm` as the package manager with a committed `pnpm-lock.yaml`. `package.json` declares the scripts `dev`, `build` (`tsc -b && vite build`), `preview`, `lint` (ESLint 9 flat config), `typecheck`, `test` (Vitest with jsdom and Testing Library), `format` and `format:check` (Prettier). `pnpm.onlyBuiltDependencies` limits post-install build scripts to `esbuild`.
- Runtime dependencies: React 19, React Router 7, TanStack Query 5, Recharts 3; Tailwind CSS 4 through `@tailwindcss/vite`; TypeScript 5.9; Vite 7.
- Directory layout `src/app`, `components`, `features`, `hooks`, `services`, `types`, `utils`, `styles`, with a `@` alias to `src` configured in `vite.config.ts` and `tsconfig.app.json`.
- `frontend-ci.yml` installs pnpm 10 on Node 22, restores the pnpm store cache keyed on `pnpm-lock.yaml`, runs `pnpm install --frozen-lockfile`, then `lint`, `typecheck`, `test`, and `build`. The workflow is a no-op when `frontend/package.json` is absent.
- `.gitignore` excludes `node_modules/`, `frontend/dist/`, `frontend/coverage/`, `frontend/playwright-report/`, and `frontend/test-results/`.

## Consequences

Positive:

- Reproducible installs from lock files in both halves of the repository.
- `uv` resolves and installs considerably faster than pip-based workflows and manages the interpreter version requirement (`>=3.12`) declared in `pyproject.toml`; the project uses Python 3.12 features such as PEP 695 generics (`def assert_transition[S]`).
- `pnpm`'s content-addressed store keeps repeated installs cheap and its strict `node_modules` layout surfaces undeclared dependencies early.
- Commands are the same on every machine and in the documentation, which lowers onboarding cost for the people and assistants working on the project.

Negative or accepted costs:

- Contributors need `uv` and `pnpm` installed; neither ships with the language runtime. The backend README lists the `uv` commands and the root `Makefile` wraps both toolchains; `frontend/README.md` lists the `pnpm` commands.
- `uv` is younger than pip and Poetry; its lock format is its own. If it were abandoned, `pyproject.toml` remains standard and could be used with another tool.
- Two lock files and two CI workflows must be kept current; dependency updates are per toolchain.

## Alternatives considered

- pip with `requirements.txt` and `venv`. Rejected: no lock file by default, slower, and separate steps for environment creation and running.
- Poetry. Workable, but slower resolution and a second configuration dialect; `uv` reads standard `pyproject.toml` metadata and dependency groups directly.
- npm or Yarn for the frontend. Both viable; `pnpm` was preferred for install speed, disk usage, and stricter dependency isolation.
