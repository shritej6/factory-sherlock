# Functional requirements

Each requirement is numbered FR-xx, grouped by module, and carries a status that reflects the code in the repository at the time of writing:

- Implemented: the behaviour exists in the backend or in `frontend/` and is reachable through the listed endpoint, module, or screen.
- Planned: not implemented; listed so the scope is explicit.

All endpoints are under `/api/v1` and require a bearer token except `GET /health`. Role requirements follow `backend/app/api/deps.py`: reads need any authenticated user; writes need the role named in the requirement. Related documents: [business-rules.md](business-rules.md) for enforced rules, [non-functional-requirements.md](non-functional-requirements.md), `docs/api/openapi.json` for the full contract.

Pagination: six list endpoints (`GET /production-orders`, `GET /production-batches`, `GET /inspections`, `GET /machines/{id}/events`, `GET /investigations`, `GET /analytics/alerts`) take `limit` (1 to 500, default 50) and `offset` (0 to 1000000, default 0) and return a page envelope `{"items": [...], "total": n, "limit": l, "offset": o}`. `total` counts every row that matches the filters, independent of the window, so a client can compute page numbers without a second request; values outside the ranges return 422 (`api/deps.py::get_page_params`, `repositories/pagination.py`, `schemas/common.py::Page`). The reference lists (`GET /products`, `GET /machines`, `GET /material-lots`, `GET /defect-types`, `GET /specifications`) return every row.
