# Test matrix

Pre-filled from the twelve required scenarios in [testing-strategy.md](testing-strategy.md). Actual result and Status were filled in by reading the automated tests under `backend/tests/` and comparing what each test asserts with the Expected result column. The last full local run of `uv run pytest` in `backend/` (2026-11-03) reported 100 passed with 95 percent coverage of `app`; that output was not saved to a file, and no CI run has been observed, so Evidence names the test files rather than a log. Status values: "Passed (automated)" means the listed test asserts the whole expected result and passed in that run; "Partly covered" means the listed tests passed but assert only part of it, and the uncovered part is stated; "Not covered by an automated test" means nothing in the test suite asserts it. The Setup and Action columns describe the intended scenario; the automated tests use their own fixtures (the `simulated` fixture seeds seed 7, 8 batches of 30 units per machine, with `TOOL_WEAR` on CNC-03 from batch index 2), so lot numbers and counts in the tests differ from the examples written here. Correction records what was changed if the expected result was not met; no expected result has been changed so far.

Conventions: all endpoints under `/api/v1`; roles refer to the seeded demo accounts; "demo data" means `uv run python -m app.seed --demo` on an empty `factory_sherlock_test` database with `APP_ENV=test`.
